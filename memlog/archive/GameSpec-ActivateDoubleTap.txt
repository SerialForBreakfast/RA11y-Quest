RA11y - Accessibility Training Gamification
Game Spec - The Rogue's Gauntlet (Activate / Double-Tap)

Date: 2026-02-20 (revised 2026-03-07 — gaps filled, ID corrected, M5 lessons applied)
Game ID: rogue-gauntlet
MVP Skill: Double-tap activation — understanding that touch ≠ action in VoiceOver

VoiceOver Paradigm Shift Taught
================================
"Tapping once no longer activates an element."
This is the single most common confusion for new VoiceOver users.
In normal iOS: tap = activate. With VoiceOver: tap = focus (examine only).
To activate the focused element, you must double-tap — anywhere on the screen.

This game makes that paradigm shift unavoidable and explicit:
  One touch → element reads aloud (examines the seal).
  Double-tap → element activates (severs the seal).
  Activating the WRONG seal springs the trap (mistake).

Theme / Narrative
=================
The Trap Room. A locked door is sealed by magical runes (seals). One seal unlocks
the door. The others spring traps. The player (rogue apprentice) must identify the
correct seal by listening to VoiceOver, then deliberately double-tap to sever it.

Touching a seal reads it aloud — that is safe. Acting without thought is not.
"Touch to sense. Double-tap to sever."

The DM speaks in all narrative prompts. The player is always "you."

Player Goal
===========
Navigate to the correct seal by its name. Double-tap to sever it. Do not spring traps.

Player Instructions (L0 Lesson Card — exact copy in GameRules-MVP.txt)
=======================================================================
"With VoiceOver on, tapping once reads an element — it does not activate it. To activate,
double-tap anywhere on the screen after focusing the element. One touch to examine.
Double-tap to sever."

Level Structure
===============
L0 — Prologue (no timer)
  DM narrates the Trap Room. Lesson card explains the paradigm shift explicitly.
  Gestures shown: tap-to-focus (one tap), double-tap-to-activate.
  Third gesture row: "Severing the wrong seal springs the trap."
  Clear contrast drawn: "This is different from normal iOS."
  "Begin Trial" button launches L1. No timer starts until L1.

L1 — First Attempt (no timer)
  VISUAL LAYOUT: A single large centered seal. No grid or list — one element only.
  Instructional text above the seal: "Touch to hear it speak. Double-tap to sever it."
  Seal: Seal of Passage (always, never randomized for L1).
  Purpose: isolate the double-tap mechanic with zero ambiguity about which seal to pick.
  The player cannot make a mistake here — only one interactive element exists.
  VoiceOver: Announce objective on level load (see "Announce Objective on Level Load" below).
  No mistake HUD displayed (no mistakes possible).
  No hint button displayed (no decoys to be confused by).
  After correct activation: thematic completion message → "Continue" → L2.

L2 — Rising Challenge (soft timer: 40s)
  VISUAL LAYOUT: 4 seals in a 2×2 LazyVGrid. VoiceOver reads row-major (left→right, top→bottom).
  1 passage seal (randomly selected from passage pool) + 3 trap seals.
  Correct seal varies per session — see "Seal Pool" and "Passage Seal Selection Rule" below.
  Wrong activation = trap springs = misstep recorded (+1 mistake).
  Timer is visible. VoiceOver announces at 50% and 25% elapsed.
  VoiceOver: Announce objective on level load.
  Hint button available (no scoring penalty).
  Mistake HUD visible.
  On timeout: session ends; timeout banner + retry button shown (no result written).
  On success: thematic completion message → "Continue" → L3.

L3 — Timed Trial (hard timer: 20s)
  VISUAL LAYOUT: 6 seals in a 2×3 LazyVGrid. VoiceOver reads row-major (left→right, top→bottom).
  1 passage seal (randomly selected from passage pool) + 5 trap seals.
  Hard time limit. Failure occurs when timer reaches 0.
  VoiceOver threshold announcements: 75%, 50%, 25%, 10s, 5-4-3-2-1 countdown.
  VoiceOver: Announce objective on level load.
  Hint button available (no scoring penalty).
  Mistake HUD visible.
  D&D timeout: "The trap room sealed. You were caught."
  D&D success: "Seal severed. The door opens just in time."
  On timeout: session abandoned; timeout banner + retry button shown (no result written).
  On success: session completed; route to shared GameResultScreen.

GameSession Scope
=================
GameSession is created ONLY for L3 (the scored Timed Trial).
L1 and L2 are practice levels with local mistake tracking only.
This matches the M5 (Enchanter's Trial) pattern and avoids polluting the
persistence layer with unscored practice data.

On each L3 start (including retries), a fresh GameSession is created.
The session is started (await session.start()) BEFORE the timer begins
to avoid the race condition where relic activation fires before the actor hop.

Announce Objective on Level Load
=================================
Per the accessibility requirement "objective card reads the correct seal name aloud
on screen load," each level view (L1, L2, L3) must post a VoiceOver announcement
when it first appears. The announcement fires with a ~500ms delay so it does not
get swallowed by the navigation-transition focus announcement.

Announced text is the full accessibility label of the objective card:
  L1: rogue.a11y.l1.objective (includes seal name + "double-tap to sever")
  L2: rogue.a11y.l2.objective (includes seal name + "careful — traps are present")
  L3: rogue.a11y.l3.objective (includes seal name + "act quickly")

Seal Pool
=========
Seal names are descriptive and distinct — no ambiguity about what each seal does.
Labels must be readable by VoiceOver and differentiated by function, not by color.
All seal assets: see DesignTicket-AssetListDefinition.txt (rogue section).

Passage Seals (correct — 1 selected per level)
-----------------------------------------------
  Seal of Passage   (always used in L1; eligible for L2 and L3)
  Warding Seal      (eligible for L2 and L3 only)
  Binding Seal      (eligible for L2 and L3 only)

Trap Seals (wrong activations = missteps)
------------------------------------------
  Spike Trap Seal
  Alarm Seal
  Collapse Seal
  Reveal Seal
  Freeze Seal
  Silence Seal

Passage Seal Selection Rule
============================
L1: Always "Seal of Passage." Never randomized.
    Reason: L1 is a confidence builder; the player needs a clear, memorable target name
    that matches the paradigm ("passage" = the way through).

L2: Randomly select 1 passage seal from the full passage pool (Seal of Passage,
    Warding Seal, or Binding Seal). Fill remaining 3 slots with trap seals, randomly
    drawn from the 6-trap pool without repetition.

L3: Randomly select 1 passage seal from the full passage pool. Fill remaining 5 slots
    with trap seals from the full trap pool. All 6 trap seals are eligible for L3.

UI testing determinism: when -uiTesting launch arg is present, always select
"Seal of Passage" and the first N trap seals (alphabetically) for predictability.

Seal Layout
===========
Seals are displayed in a LazyVGrid (2 columns).
- L2: 2×2 grid (4 seals, 2 columns × 2 rows).
- L3: 2×3 grid (6 seals, 2 columns × 3 rows).
VoiceOver reads LazyVGrid in row-major order (left → right, then next row), which is
linear and deterministic — equivalent to a vertical list for accessibility purposes.
The grid layout is preferred for thematic reasons: seals visually occupy a door face.

Retry Button Behavior
======================
L1: No retry button — no mistakes possible; "Continue" button after success only.
L2: Retry button shown ONLY in the timeout state. Success shows "Continue."
L3: Retry button shown in both timeout state and (no retry on success — goes to results).
    On retry: fresh session created, new seal layout randomized, timer resets.

Art / Assets
============
Each seal is a distinct glyph/rune sprite (rogue_seal_*).
Background: rogue_trap_door_bg.
All assets exist in Assets.xcassets as of 2026-03-07.
Flat, high-contrast, vector-like; no text in images.
See DesignTicket-AssetListDefinition.txt (rogue section).

Gameplay Loop
=============
1. L0 lesson card presented. Player reads (or VoiceOver reads) the paradigm shift.
2. "Begin Trial" starts L1.
3. L1: Single seal displayed. Objective announced on load. Player double-taps to sever.
4. L1 success → thematic message → Continue → L2.
5. L2: 4 seals displayed. Objective announced on load. 40s timer visible.
6. Player touches seals to hear each name read aloud (focus only).
7. Player double-taps when focused on the correct seal to sever it.
8. Wrong seal double-tapped → trap springs → misstep + feedback → player continues.
9. L2 success → thematic message → Continue → L3.
10. L3: 6 seals displayed. Objective announced on load. 20s hard timer starts.
11. Correct activation → session completed → route to GameResultScreen.
12. Timeout (L2/L3) → session abandoned (L3 only) → timeout banner + retry shown.

Observable Signals (Measurable)
================================
Primary
- Correct seal button activation handler invoked (success).

Secondary
- Trap seal button activation handler invoked (mistake: +1).
- Elapsed time (monotonic clock, L3 session).
- Timeout fired (fail/abandon).

Scoring
=======
Metrics
- timeSeconds: from L3 session.start() to correct seal activation (or timeout).
- mistakes:
  - +1 per wrong seal activation (trap sprung).
  - +1 per timeout bucket exceeded (bucket: 8s; see below).

Timeout Bucket
--------------
- Bucket size: 8 seconds.
- Each full 8s bucket beyond the first adds +1 mistake.
  Example: 0–8s → +0; 8–16s → +1; 16–24s → +2.
- Formula: max(0, ceil(timeSeconds / 8.0) - 1)  [same as M5 bucketMistakes, different size]
- Tunable post-playtest.

Rank Thresholds
---------------
  Legendary (Perfect): mistakes == 0 AND timeSeconds <= 8
  Skilled   (Good):    mistakes <= 1 AND timeSeconds <= 16
  Novice    (Ok):      success AND timeSeconds <= 40
  Defeated  (Failed):  timeout at 40s OR mistakes >= 5

Game-Specific Result Announcements
===================================
Displayed on the shared results screen after L3 completes.
The SharedGameResultScreen accepts a game-specific announcement string.

  Legendary: "Flawless. No trap touched you. The Guild is impressed."
  Skilled:   "Skilled hands. One misstep, but the door opened."
  Novice:    "The trap room tested you. You escaped — barely."
  Defeated:  "The trap room claimed you. Study the seals and return."

Failure States + Mitigations
=============================
- Accidental wrong activation:
  - Ensure adequate spacing and distinct seal labels (no two seals sound alike).
  - Feedback is immediate and non-punishing in tone: "Trap sprung. Misstep."
- Player doesn't understand double-tap:
  - Optional hint (no penalty): "The DM whispers: double-tap to sever a seal."
  - Hint re-announces the mechanic via VoiceOver.
- Player is stuck:
  - "Try Again" resets the current level (L2/L3 only — L1 has no mistakes).

Accessibility Requirements
===========================
- All seals: accessibilityLabel (seal name) + accessibilityHint ("Double-tap to sever.").
- Objective card: accessibilityLabel includes correct seal name + full instruction.
- Trap activations give clear feedback via VoiceOver announcement.
- Reading order is deterministic and linear (vertical list order — seals in display order).
- Timer group (L2/L3): single accessibility element; NOT updated every second.
  Announced only at defined thresholds (see GameRules-MVP.txt timer spec).
- L1 note: single seal, no navigation instruction needed. Focus is on teaching
  the double-tap mechanic in isolation.
- Objective announced on level load (~500ms delay to clear transition noise).

- bestResult(lhs:rhs:) -> GameResult  [covered by existing ScoringModelTests]
- sealSetForL2() returns exactly 1 passage seal + 3 trap seals
- sealSetForL3() returns exactly 1 passage seal + 5 trap seals
- L1 always returns Seal of Passage (id: "passage")
