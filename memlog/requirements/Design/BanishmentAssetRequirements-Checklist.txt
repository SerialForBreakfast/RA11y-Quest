Banishment — Asset requirements, traceability, and verification
================================================================
Date: 2026-04-23
Status: Living checklist (update in the same commit as catalog or Swift changes)

Purpose
-------
Make Banishment art **accountable**: every required file is listed, authored
(LLM or human per Phase 4–5), ingested mechanically, integrated under known Swift
names, and verified by automation before screenshots ship.

**Authorship:** Root `AGENTS.md` — *Illustrated quest assets — authorship (mandatory)*.
Do not use procedural scripts to paint shipping art; use LLM/human pixels, then
`utility/ingest_llm_banishment_pngs.py` or manual catalog placement.

Process diagnosis (why progress felt stuck)
------------------------------------------
- The design docs were sound; **execution gaps** were:
  1. **No automated gate** before screenshots / release that failed on bad PNGs.
  2. **Procedural placeholders** could be technically valid but visually empty
     (tiny compressed masters) — humans read that as “broken asset”.
  3. **Illustrated exports** (mockups / ImageGen) are a separate phase from
     “greybox procedural” — the repo did not enforce “replace placeholders”
     as a milestone.
  4. **Prologue** has no catalog illustration in `iOSBanishmentArt` — mockups
     that show a hero frame are **not yet modeled** in SwiftUI.

Single source of truth (update order)
-------------------------------------
When adding or renaming an asset, touch **all** of these in one commit:

  1. `RA11y-iOS/RA11y-iOS/Games/iOSBanishmentArt.swift` — string constants
  2. `utility/qa_banishment_png_assets.py` — `BANISHMENT_REQUIRED` / `OPTIONAL`
  3. `RA11y-iOS/RA11y-iOS/Assets.xcassets/<name>.imageset/` — PNG + Contents.json
  4. `memlog/requirements/Design/BanishmentAssetPipeline.txt` — layer stack text
  5. `RA11y-iOS/RA11y-iOSTests/RA11y_iOSTests.swift` — `BanishmentArtCatalogTests`
  6. This checklist — matrix row + notes

Verification commands (Definition of Done for a catalog change)
----------------------------------------------------------------
  1. Refresh PNGs: `python3 utility/import_banishment_mockups_to_assets.py` (or replace mockups in `MockupScreens/` first).
  2. `bash utility/validate_banishment_assets.sh`
       — FAIL on missing required set, wrong background size, RGB sprites, or
         backgrounds flatter than `MIN_BG_LUMA_SAMPLE_VARIANCE` in qa script.
       — Optional CI hardening: append `--strict-warnings` (treats WARN as FAIL).
  3. `xcodebuild test -workspace RA11y.xcworkspace -scheme RA11y-iOS -destination 'platform=iOS Simulator,name=iPhone 16' -only-testing:RA11y-iOSTests/BanishmentArtCatalogTests`
       — or run full `RA11y-iOSTests` target.
  4. `bash utility/validate_screenshot_contract.sh` (screenshot route alignment).
  5. `bundle exec fastlane ios screenshots` — human sign-off on
     `13_`–`16_Banishment*.png` for iPhone_large, iPhone_small, iPad.

Iteration: replacing procedural art with illustrated exports
--------------------------------------------------------------
  1. Produce PNGs at the **spec size** above (avoid uncropped phone mockup frames
     as full-bleed backgrounds — use portrait masters).
  2. Sprites must be **RGBA** with real alpha (see qa script RGB FAIL).
  3. Drop files into the existing `.imageset` folders (or extend import script).
  4. Re-run steps 2–5 under Verification.
