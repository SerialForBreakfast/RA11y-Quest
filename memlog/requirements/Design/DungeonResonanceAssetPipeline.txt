RA11y — Dungeon Resonance v2 Asset Pipeline
============================================
Date: 2026-04-19
Related: ADR-0003, DesignTicket-DungeonResonancePromptSheet.txt

Purpose
-------
Describe how generated PNGs compose in SwiftUI across iPhone and iPad: sizes,
transparency, scaling, and layer order so art and code stay aligned.

Catalog location
----------------
All images live under:
  RA11y-iOS/RA11y-iOS/Assets.xcassets/
as one **universal** imageset per asset (single 1x PNG each), matching existing
dungeon art (`dungeon_descent_bg`, `dungeon_room_*`). Xcode scales the same
bitmap on all devices; future @2x/@3x exports can be added without renaming.

Layer stack (back → front)
--------------------------
1. `dungeon_resonance_bg` — full-bleed; `.scaledToFill()` + `.clipped()`; ignores safe
   area where the scene should read edge-to-edge.
2. Scroll lane — moonstone, decoys, lane markers as **row content**; horizontal
   padding and optional `frame(maxWidth: 560…640)` keeps the lane readable on iPad.
3. `dungeon_reticle_ring` — fixed center; drawn **under** the orb per design ticket.
4. `dungeon_resonance_orb_idle` or `dungeon_resonance_orb_locked` (or idle + code glow) —
   fixed center; `allowsHitTesting(false)` so scroll passes through.
5. Optional `dungeon_success_flare` — short-lived overlay on Success; compose with
   `.opacity` + blend mode; respect Reduce Motion (skip or shorten).
6. Lights Off: darken world with **code** radial gradient **plus** optional
   `dungeon_spotlight_mask_reference` multiply/softLight; orb and reticle stay
   fully opaque above the mask.

Runtime sizing (SwiftUI)
------------------------
Use **points**, not raw pixels. Recommended defaults (tune in mockup / final game):

- **Background:** GeometryReader or `containerRelativeFrame`; minimum dimension fill;
  accept crop on ultra-wide; center band of art should remain calm (prompt requirement).
- **Orb:** `@ScaledMetric(relativeTo: .title)` base **112 pt** diameter, clamp 88–140 pt;
  same visual weight on iPhone and iPad.
- **Reticle ring:** ~1.45–1.55× orb diameter so the ring frames the orb without
  covering it; single asset scales with `.resizable` + `aspectFit` in a square frame.
- **Moonstone (target):** ~72–96 pt wide (oval); decoys same order of magnitude; distinct
  silhouettes remain readable at Dynamic Type–adjacent sizes.
- **Lane marker:** low visual weight; ~22–28 pt height bars or proportional glyph.

Transparency rules
------------------
- **Opaque:** `dungeon_resonance_bg` only.
- **Alpha:** all other listed assets. Subjects centered with **padding inside the PNG**
  so SwiftUI can scale without clipping highlights.
- **Glyph lane exports:** `dungeon_target_moonstone`, `dungeon_decoy_*` shipped historically as
  **RGB-only** wide canvases; SwiftUI drew obvious grey/light boxes around scaled glyphs. They
  must be **PNG RGBA** (true alpha). If a revision lands as flat RGB again, run
  `utility/remove_white_background.py --mode edge` on edge-connected near-white (backs up then
  replaces in place), or re-export from the art pipeline with proper alpha. Review on a dark
  background (game shaft) on device.

Multiple form factors
----------------------
- **Single universal bitmap** keeps repo small; tradeoff is sharpness on large iPad /
  Pro Max. Acceptable for v2 prototype; add @2x later from same masters if needed.
- **iPad:** Cap lane content `maxWidth` (~600) and center in scroll so fixed center
  orb aligns with the **viewport** center (not the full width content column).

Naming stability
----------------
Imageset names match prompt filenames (`dungeon_resonance_bg`, etc.). Renames require
a single coordinated change: asset catalog + Swift string constants + docs.
