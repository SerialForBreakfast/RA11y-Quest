RA11y - Accessibility Training Gamification
Game Spec - The Rogue's Gauntlet (Activate / Double-Tap)

Date: 2026-02-20 (revised to align with GameRules-MVP.txt)
Game ID: bomb_defusal_wires
MVP Skill: Double-tap activation — understanding that touch ≠ action in VoiceOver

VoiceOver Paradigm Shift Taught
================================
"Tapping once no longer activates an element."
This is the single most common confusion for new VoiceOver users.
In normal iOS: tap = activate. With VoiceOver: tap = focus (examine only).
To activate the focused element, you must double-tap — anywhere on the screen.

This game makes that paradigm shift unavoidable and explicit:
  One touch → element reads aloud (examines the seal).
  Double-tap → element activates (severs the seal).
  Activating the WRONG seal springs the trap (mistake).

Theme / Narrative
=================
The Trap Room. A locked door is sealed by magical runes (seals). One seal unlocks
the door. The others spring traps. The player (rogue apprentice) must identify the
correct seal by listening to VoiceOver, then deliberately double-tap to sever it.

Touching a seal reads it aloud — that is safe. Acting without thought is not.
"Touch to sense. Double-tap to sever."

The DM speaks in all narrative prompts. The player is always "you."

Player Goal
===========
Navigate to the correct seal by its name. Double-tap to sever it. Do not spring traps.

Player Instructions (L0 Lesson Card — exact copy in GameRules-MVP.txt)
=======================================================================
"With VoiceOver on, tapping once reads an element — it does not activate it. To activate,
double-tap anywhere on the screen after focusing the element. One touch to examine.
Double-tap to sever."

Level Structure
===============
L0 — Prologue (no timer)
  DM narrates the Trap Room. Lesson card explains the paradigm shift explicitly.
  Gestures shown: tap-to-focus (one tap), double-tap-to-activate.
  Clear contrast drawn: "This is different from normal iOS."
  "Begin Trial" button launches L1.

L1 — First Attempt (no timer)
  1 seal only (the Seal of Passage). No decoys.
  Purpose: build confidence that touch-then-double-tap works.
  The player cannot make a mistake here — only one interactive element exists.
  "Touch it to hear it speak. Double-tap to sever it."

L2 — Rising Challenge (soft timer: 40s)
  4 seals: 1 correct (Seal of Passage) + 3 trap seals with distinct names.
  Correct seal varies per session (any from the passage seal pool).
  Wrong activation = trap springs = misstep recorded.
  Timer is visible. VoiceOver announces at 50% and 25% elapsed.

L3 — Timed Trial (hard timer: 20s)
  6 seals: 1 correct + 5 traps. Drawn from full seal pool.
  Hard time limit. Failure occurs when timer reaches 0.
  VoiceOver threshold announcements: 75%, 50%, 25%, 10s, 5-4-3-2-1 countdown.
  D&D timeout: "The trap room sealed. You were caught."
  D&D success: "Seal severed. The door opens just in time."

Seal Pool
=========
Seal names are descriptive and distinct — no ambiguity about what each seal does.
The correct "passage" seal is drawn from the passage pool. Trap seals are drawn from
the trap pool. Labels must be readable by VoiceOver and differentiated by function,
not by color.

Passage Seals (correct — 1 selected per level)
  Seal of Passage
  Warding Seal
  Binding Seal

Trap Seals (wrong activations = missteps)
  Spike Trap Seal
  Alarm Seal
  Collapse Seal
  Reveal Seal
  Freeze Seal
  Silence Seal

L1 uses: Seal of Passage only (always).
L2 uses: 1 passage seal + 3 trap seals.
L3 uses: 1 passage seal + 5 trap seals.
Selection is randomized per session.

Gameplay Loop
=============
1. L0 lesson card presented. Player reads (or VoiceOver reads) the paradigm shift.
2. "Begin Trial" starts L1.
3. Game displays seals on the door. Objective card announces which seal to sever.
4. Player touches seals to hear each name read aloud (focus only).
5. Player double-taps when focused on the correct seal to sever it.
6. Wrong seal double-tapped → trap springs → misstep + feedback → player continues.
7. Correct seal double-tapped → level success → brief feedback → next level (or results).
8. Timeout (L2/L3) → session abandoned → no result written.

Observable Signals (Measurable)
================================
Primary
- Correct seal button activation handler invoked (success).

Secondary
- Trap seal button activation handler invoked (mistake: +1).
- Elapsed time (monotonic clock).
- Timeout fired (fail/abandon).

Scoring
=======
Metrics
- timeSeconds: from "Begin Trial" tap to correct seal activation (or timeout).
- mistakes:
  - +1 per wrong seal activation (trap sprung).
  - +1 per timeout bucket exceeded (bucket: 8s; see below).

Timeout Bucket
--------------
- Bucket size: 8 seconds.
- Each full 8s bucket beyond the first adds +1 mistake.
  Example: 0–8s → +0; 8–16s → +1; 16–24s → +2.
  Tunable post-playtest.

Rank Thresholds
---------------
  Legendary (Perfect): mistakes == 0 AND timeSeconds <= 8
  Skilled   (Good):    mistakes <= 1 AND timeSeconds <= 16
  Novice    (Ok):      success AND timeSeconds <= 40
  Defeated  (Failed):  timeout at 40s OR mistakes >= 5

Game-Specific Result Announcements
===================================
These are displayed on the shared results screen after L3 completes.
The SharedGameResultScreen accepts a game-specific announcement string.

  Legendary: "Flawless. No trap touched you. The Guild is impressed."
  Skilled:   "Skilled hands. One misstep, but the door opened."
  Novice:    "The trap room tested you. You escaped — barely."
  Defeated:  "The trap room claimed you. Study the seals and return."

Failure States + Mitigations
=============================
- Accidental wrong activation:
  - Ensure adequate spacing and distinct seal labels (no two seals sound alike).
  - Feedback is immediate and non-punishing in tone: "Trap sprung. Misstep."
- Player doesn't understand double-tap:
  - Optional hint (no penalty): "The Enchanter reminds you: double-tap to sever."
  - Hint re-announces the mechanic via VoiceOver.
- Player is stuck:
  - "Try Again" resets the current level.

Accessibility Requirements
===========================
- All seals: accessibilityLabel (seal name) + accessibilityHint ("Double-tap to sever.").
- Objective card: accessibilityLabel includes correct seal name + instruction.
- Trap activations give clear feedback via VoiceOver announcement.
- Reading order is deterministic (seals in consistent layout order).
- Timer group: single accessibility element; NOT updated every second.
  Announced only at defined thresholds (see GameRules-MVP.txt timer spec).
- L1 note: because only one element exists, no navigation instruction is needed;
  focus is on teaching the double-tap mechanic in isolation.

Unit-Testable Logic
====================
- rankFor(timeSeconds:mistakes:) -> GameRank
- bucketMistakes(timeSeconds:bucketSize:) -> Int
- bestResult(lhs:rhs:) -> GameResult
