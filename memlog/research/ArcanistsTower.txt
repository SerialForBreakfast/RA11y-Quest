⚗️
The Arcanist's Tower (historical working title)
Rotor Quest — Game Design Document
RA11y-Quest  ·  v1.0 Draft


Overview
The Arcanist's Tower was an early working title for RA11y’s navigation-rotor quest. Where The Enchanter's Trial teaches swipe-to-navigate and Crystal Resonance teaches three-finger scroll, that quest teaches the VoiceOver rotor — the control that changes what **next and previous flicks** move between.

The framing in this draft: ascending a wizard's tower floor by floor. **v1 product copy** instead uses **The Threefold Seal** / signed-archive language (see QuestConcept). The rotor is the platform navigation **mode picker**. Choosing the wrong setting still wastes time because flicks do not land on the right element class.



Quest Arc at a Glance


L3 (Form Controls) and L5 (Characters) are reserved for a future milestone. The Boss floor draws only from the implemented levels.

L0 — The Arcanist Speaks
Purpose
Introduce the rotor before the player attempts anything. The Arcanist explains the gesture, names the spell wheel, and sets expectations. The player cannot proceed until they have dismissed the lesson card.

Narrative


Mechanics
Static lesson card — no interaction required beyond dismissal
Animated diagram shows two-finger rotation gesture
VoiceOver reads the full Arcanist monologue as an accessibility announcement on screen load
Continue button is the only interactive element

Accessibility Notes
accessibilityLabel on the diagram: "Two fingers rotating clockwise on screen, revealing a menu of rotor options"
Continue button hint: "Double-tap to ascend to the first floor"
No timer, no score, no failure state

L1 — The Codex Floor


Narrative Setup


Core Mechanic — Treasure Hunt
The screen is a long scroll of lore text with 8 chapter headings. The Arcanist reads a riddle aloud at the start ("The answer sleeps beneath the Chapter of Ash"). The player must:
Invoke the rotor and select Headings
Swipe down to jump heading-by-heading through the Codex
Identify and double-tap the named chapter

Swiping without setting the Headings rotor first moves through every element — the lore text is dense enough that brute-force swiping is visibly painful. The rotor is not optional; it's the only practical path.

Heading Design
Headings are crafted to require listening, not guessing. Several are thematically adjacent:
Chapter of Ash  /  Chapter of Cinders
The Iron Compact  /  The Iron Accord
Verse of Flame  /  Verse of Ember

The target heading is randomised each run from a pool, so the riddle always refers to the correct chapter.

Failure State
Activating the wrong chapter: "The Vault shudders — that is not the chapter. -5 seconds."
Timer expires: "The Vault seals. The knowledge is lost." → Defeated rank

Scaffolding Across Sub-levels


Accessibility Notes
Each heading has a clear, distinct accessibilityLabel
Penalty announcement is made via accessibilityAnnouncement, not visual-only
Timer announces at 50% and 25% elapsed — never continuously
VoiceOver focus moves to the first heading automatically on screen load

L2 — The Tome Floor


Narrative Setup


Core Mechanic — Rune Hunt
The screen shows a dense page of lore prose. Embedded within are 6 link elements styled as glowing runes. The player must:
Invoke the rotor and select Links
Swipe to enumerate only the rune-links, skipping surrounding text
Identify the named rune by its accessibilityLabel
Double-tap to activate it

Without the Links rotor, the player must swipe through all body text to reach each rune. The text is deliberately long — the rotor is the only practical way to scan runes efficiently under the timer.

Rune Label Design
Rune labels are chosen to require careful listening. Near-identical pairs appear in the pool:
Seal of Binding  /  Seal of Bonding
Ember Rune  /  Ember Mark
Shadow Glyph  /  Shadow Sign
Rune of Passage  /  Rune of Passing

Only one rune-link is the target. The rest are traps. The target is randomised per run.

Failure States
Wrong rune activated: "A trap springs — shadows close in. -10 seconds."
Timer expires: "The seal holds. The tome burns." → Defeated rank

Scaffolding Across Sub-levels


Accessibility Notes
Each rune-link has a distinct accessibilityLabel and accessibilityHint: "Double-tap to invoke this rune"
Trap activation announcement is immediate and unambiguous
Surrounding lore text elements are marked accessibilityElementsHidden: false — they must be present to make the rotor feel valuable
Timer behaviour mirrors L1

L4 — The Archery Floor


Narrative Setup


Core Mechanic — Arrow Draw
The screen shows a bow-and-target interface. A draw weight indicator (an adjustable SwiftUI element) represents how far the bow is drawn. The player must:
Invoke the rotor and select Adjustable
Swipe up to increase draw weight, swipe down to decrease
Land on the exact required value — VoiceOver announces the current value on each swipe
Double-tap to fire

The mapping is physical and intuitive: swipe up = pull the string back further. The Adjustable rotor + vertical swipe mirrors the actual gesture model exactly.

Arrow Sequence


Feedback Model
Undershoot: "The arrow falls short. The lock holds." — visual arrow drops below target
Overshoot: "Too much force — the arrow shatters the frame." — visual arrow punches through
Hit: "The lock cracks. One seal broken." — satisfying haptic + audio
All three hit: gate opens, floor complete
Any miss: arrow attempt is consumed; 3 misses in a run contributes to lower rank

Why Adjustable Rotor is Required
The draw weight element is a custom adjustable element. Without selecting the Adjustable rotor, vertical swipes scroll the page rather than adjusting the value. The player will swipe up and nothing will happen to the bow — the failure is immediate and instructive.

Scaffolding Across Sub-levels


Accessibility Notes
Draw weight element: accessibilityLabel "Draw weight", accessibilityValue "[n] of [max]"
accessibilityIncrementHandler / decrementHandler drive the value
Required weight announced on each arrow: "The enchantment requires a draw of 7"
Current value announced on every swipe step by VoiceOver natively via the Adjustable trait
Timer announces at 15 seconds and 5 seconds remaining

Boss — The Shifting Tower


Narrative Setup


Core Mechanic — Random Floor Order
Each run presents 5–7 challenges drawn randomly from the floor pool (L1 Codex, L2 Tome, L4 Archery). No hint is given about which rotor is needed. The player must read environmental cues and select the correct setting before acting.

Environmental Cue Design
Each floor type has a consistent visual and audio identity that signals the required rotor without stating it:


Scoring
The Boss is scored on two dimensions: completion and efficiency.
Rounds completed within 60 seconds → base score
Each wrong rotor selection that wastes time → penalty applied to rank calculation
Perfect run (correct rotor first try, every round) → Legendary rank
All rounds complete with errors → Skilled or Novice depending on time remaining
Timer expires mid-run → Defeated regardless of rounds completed

Replayability Design
The randomised floor order means memorisation is not a path to Legendary rank — correct rotor selection judgment is. A player who genuinely understands the rotor will score consistently across runs. A player who memorised the tutorial order will be exposed immediately.



Accessibility Notes
Each floor transition is announced: "The tower shifts. A new room forms around you."
No visual-only indication of floor type — audio and VoiceOver cues carry full meaning
Timer announces at 30 seconds, 15 seconds, and 5-4-3-2-1 countdown
Wrong rotor selection: VoiceOver announces what the current rotor found ("No headings found" or "No links found") — instructive, not punitive

Open Questions
L3 (Form Controls): scenario TBD — postponed pending a mechanic that genuinely requires the rotor rather than tolerating brute-force swiping
L5 (Characters): Corrupted Glyph mechanic approved in principle — postponed pending L3 resolution
Boss round count: 5 vs 7 — depends on how long individual floor challenges take in playtesting
Rank thresholds for Boss: need calibration against real completion times
Lights Off variant: post-M8 consideration — Boss floor with screen curtain engaged
